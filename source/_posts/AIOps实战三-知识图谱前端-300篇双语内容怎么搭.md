## 一、内容从哪来

图谱现在有 **13 个主题区、300 个节点**。内容来源分两块：

- **293 篇翻译内容**：原本是英文的 SRE / DevOps 路线图，我用脚本批量翻译、补上中文三段（标题、摘要、深度解读、资源、里程碑、边上的"下一步去哪"问题）。
- **7 篇自研 AIOps**：`content/aiops/` 下我自己写的，比如"多智能体编排闭环：Dify + StackStorm"，是引擎那套理念的教学版。

翻译不是 Ctrl+C/V：每篇要落 `title_zh` 字段 + 正文里 `<!-- ZH_SUMMARY -->` / `<!-- ZH_DEEP_DIVE -->` / `<!-- ZH_RESOURCES -->` 三个中文块，外加 `<!-- ZH_UI -->` 编号列表装 UI 文案（里程碑、边上的问题与选项）。

## 二、双语怎么切换

核心是一个 React Context（`LanguageProvider` / `useLang`）：

- 状态存 `localStorage` 的 `lang` 字段（`zh` / `en`），默认中文；
- 右上角一个「中 / EN」按钮切换，顺手把 `document.documentElement` 的深浅色也切了；
- 渲染时按 `lang` 决定读英文块还是中文块，节点卡片、弹窗、搜索都跟着变。

搜索也双语：Fuse.js 同时索引 `title` 和 `titleZh`，中文搜中文、英文搜英文都能命中。

## 三、图的"渐进展开"是怎么做的

这是图谱最好用的地方——不是一上来把 300 个节点全铺开，而是：

1. **找根节点**：`findRoots` 看哪些节点没有入边，作为入口；
2. **只展开下一层**：`getInitialVisibleNodes` 先把根 + 直接子节点显示出来；点一个节点才展开它的下游；
3. **边是"问题"不是"标题"**：两个节点之间的连线，写的是学习者真会问的话（"我想不用每次手敲 SSH 修东西，有没有更好的办法？"），中间插一个 `questionNode` 显示这个问题。
4. **跨区用"门户"**：A 区的某个节点指向 B 区，就插一个 `zonePortalNode`，点它跳到 B 区。

> 踩坑：AIOps 区 7 个节点形成了环（rag → overview → …），`findRoots` 返回空 → 整个图空白。后来加了**环图回退**：所有节点都有入边时，选入边最少的节点当入口，平手优先 id 含 `overview/intro/start` 的。现在稳定。

## 四、几个真踩过的坑

- **CRLF 把翻译吞了**：Windows 下翻译文件是 CRLF，解析 `ZH_UI` 编号列表时用 `split("\n")` 没切掉 `\r`，导致 293 篇的中文 UI 全空。改成 `split(/\r?\n/)` 才修好。
- **构建污染**：`next build` 和 `next dev` 共用 `.next`，我一度在 dev 跑着时又 build，把客户端 bundle 搞坏、图整片 `opacity:0` 空白。删 `.next` 重起 dev 才恢复。
- **Hexo 同款提醒**（如果你用博客存这些 md）：YAML frontmatter 里十六进制 `abbrlink` 必须加引号，不然被解析成浮点、链接直接坏。

## 五、想加一个新主题区
